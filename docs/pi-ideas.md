# Ideas to improve the Pi setup

## Purpose

Collect researched candidate improvements to the Pi setup for later review.

Written 2026-10-03. Sources: other coding agents (Codex CLI, Gemini CLI, Antigravity, Cursor CLI, Aider, Cline, Roo Code, Goose, Amp, Factory Droid, Crush, Kimi CLI, Qwen Code, Continue, Zed, Warp, GitHub Copilot CLI, Kiro), real Pi configurations and write-ups, and Pi's own docs and example extensions. Claude Code, oh-my-pi, and OpenCode were compared earlier and are not repeated here.

**Nothing here is decided or installed.** Items already decided in [pi-research.md](pi-research.md) are not re-proposed. Parked items (capability 7) appear only where research found a new angle.

## How to read the tables

- **Filter:** every idea was judged against the setup's constraints: audited and pinned packages only, minimal surface, small readable extensions preferred over packages, cheap main model with strong reviewers, solo use, Rust and Bevy creative coding, explicit confirmation before commits and pushes.
- **Effort:** S is under an hour of work, M is a few hours, L is a day or more.
- **How in Pi:** *setting*, *example extension* (shipped with Pi), *small extension* (own code), *template* (prompt template), *skill*, *AGENTS.md rule*, *script*, or *habit*.
- **Verified** means checked in Pi's installed docs or code on this machine. Claims taken from a vendor page or a third-party article are marked as such. **Unverified** means not confirmed anywhere.
- Flags in the notes column: **net** (new network access or third-party endpoint), **unattended** (runs without a prompt), **deps** (new dependencies).

## Seen and not proposed

| Item | Reason |
|---|---|
| Completion loops (`ralph-loop`, `pi-goal`, `/goal`) | **unattended** runs, which conflicts with explicit confirmation |
| An auto-update extension ([dotpi](https://github.com/jwmarb/dotpi) checks every 4 hours) | Conflicts with exact pinning |
| `file-trigger.ts` example and `/control` cross-session sockets | Inbound channels that inject messages into a session |
| TypeSafe "Jev" features (`pi-warden`, `autoFollowUp`, the router example as shipped) | Third-party endpoint |
| Codex-style fast-mode toggles | Reported to use about twice the tokens for speed ([Kun](https://blog.kunchenguid.com/p/kuns-pi-agent-config)); a cost increase |
| `git-hooks.ts` that arms `core.hooksPath` itself (dotpi) | Changes git config automatically; ideas 1 and 2 do it explicitly instead |
| Browser automation skills and extensions | Large surface; visual testing stays manual |
| Rust type-information MCP servers ([cursor-rust-tools](https://github.com/terhechte/cursor-rust-tools)) | A second `rust-analyzer` instance; the LSP idea was skipped for token and startup cost |
| A remote web supervisor for sessions | Remote access surface |

## Prioritized shortlist

1. **Agent-only git hooks (idea 1, with 2):** a mechanical push lock and commit attribution under the permission rules, for under an hour.
2. **`shellCommandPrefix` with `CARGO_BUILD_JOBS=4` (idea 26):** turns the `-j 4` rule into something the model cannot forget.
3. **Prompt templates (idea 13):** a built-in feature that is unused, and `/review`, `/commit-msg`, and `/spec` come back every week.
4. **Version-exact Bevy rule (idea 59):** the original problem, stale APIs, recurs on every Bevy release.
5. **Keep the permission harness in the repo (idea 39):** it exists only in a temporary directory today, and the rules matter.
6. **Live smoke-test checklist (idea 40):** closes every "untested" item in one session.
7. **Vet-diff script and pin-bump cadence (ideas 53 and 54):** closes the open pin-bump policy item with the checklist already written.
8. **Private config repo (idea 52):** reproducibility and backup for a setup that took real effort to build.
9. **Taint-aware outbound gate (idea 3):** targets the one real exposure the setup chose: `curl`/`wget` allowed next to web fetch.
10. **Pre-commit review by another model (idea 36):** about $0.07 for an independent check on each diff, with the permission behavior in `-p` to test first.
